本轮审计发现 5 处「好看但不成立 / 静默失真」的通道，已全部修复并落成机器闸； 修复后所有池的出票结论 在同一口径下重算，历史留痕未被改写。

修复 2 · 出票许可返回值语义反义

问题：emit_license() 顶层曾返回 "ok": not any(...) —— 名字叫 ok、实际表示「全部不出票」， 与 detail 内同名字段反义。_rev_gate_page.py 直接拿它显示， 于是「本期许可」恒显示「见表」，永远不显示「不出票」。
修复：顶层改名为语义正向的 any_ok / all_blocked， 调用点同步。反转证据页现正确显示「全部档位不出票」。

修复 3 · K 线缓存无新鲜度校验

问题：_tx_fetch.fetch_kline 命中缓存只看条数 （len ≥ n-8）、不看末根日期，旧价会被静默当作当日价算指标。 实测缓存 8 / 5049 只（0.16%） 末根 < 2026-09-30，另有 5 个非股票代码 （可转债）混入。
修复：新增 set_asof() / stale_codes() / is_stock()； 命中缓存时校验末根 ≥ asof，陈旧则自动重新联网补拉；日更第一步 _datahub.py 钉住当期数据日，底座 manifest 落 kline_freshness； 门禁加第 ⑥ 项：陈旧占比 > 2% 判失败。

修复 4 · 融资信号覆盖不足（数据有效性闸）

问题：增仓池 S/A 档的核心判据之一是 M 维（融资增仓）。 实测面板期 M 维候选覆盖仅 18.4%， 其中 44 个入场日完全拿不到 M 信号 —— 统计再漂亮也是拿缺维数据算出来的。
修复：新增「数据有效性闸」（与统计无关的前置条件）， 覆盖率低于 30% → 该池全档不出票； 覆盖率逐日写入证据页覆盖度表。

修复 5 · bootstrap 参数不可复现

问题：脚本默认 --boot 800、既有证据用 2000， 同一份数据两次跑出不同 R3（S 档 20 日 0.921 vs 0.9175），结论不可复现。
修复：BOOT 固定为 2000 并写入产物 boot 字段； 重跑后 per.stat 逐位复原，唯一变化的是 allow。

修复 6 · 日K主缓存：39 个脚本各解析一遍 128MB，且缺文件时行为不一

问题：_txk_cache.json（实测 128.5 MB / 5049 票） 曾被 0 个脚本各自 json.load；_rev_lab.py 一个脚本里就 load 3 次（105 / 344 / 562 行），同一次跑里同一份 128MB 被解析三遍。 各家缺文件行为还分叉：有的静默 {}、有的抛异常。 更要紧的是——txk 是主缓存，很多脚本直接拿它当「当日价」，旧数据冒充当日的后果比长K更直接。
修复：新增唯一入口 _txk.py——mtime 感知的进程内共享缓存 （写回自动失效，不会读到旧版本）+ set_asof() 陈旧即 fail-safe 返回空 + src_label() 把「数据截至 X」标进产物 + 可选日志 WB_TXK_LOG。 实测：同一进程内 3 次 load，由 3×0.579s 降到 1×0.579s + 2×0.00002s； _txk.load() 与直读内容完全等价（5049 票逐票一致）。
过程中现场抓到的 fail-open：陈旧拦截第一版「只把 stale_blocks 加一， 仍然把 5049 条旧数据交出去」——计数与拦截不一致，正是「有该键 ≠ 已通过」。 修法：拦截必须在「返回」之前，判据收敛到 _stale_hit() 单一真源； 钉对日期后缓存自动恢复，不需要重抓。

修复 7 · 结论文件键序随 hash seed 漂移，产物每次字节都变

现象：_env_gate_lab.json 每次跑字节都不同， 连 PYTHONHASHSEED=0 下连跑两次都能对不同 hash。
定位：PYTHONHASHSEED 取 0/1/2/3 → 四个不同 hash； 但把两份产物 json.dumps(sort_keys=True) 比较 → 完全一致，数值差异 0 处。 根因是 日期串作 dict 键（esc / elab / by_sc）， dict 迭代序随字符串 hash 变 → 只是输出键序漂，bootstrap 数值没动（页面数字是稳的）。
修复：json.dump(..., sort_keys=True) 把键序钉死。 修复后 PYTHONHASHSEED 取 0 / 1 / 7 → 三份字节完全一致（均 8760 字节）。 数值不受影响，但文件可复现了，幂等门禁不会再被误判成「改了东西」。
