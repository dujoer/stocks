二、每日盘后标准流程

① 龙虎榜主看板（必做，自动化）

1. 拉取并落盘（收盘后 ≥15:30，交易日）：用 westock-mcp 拉取并写文件到 quant/ 对应子目录，文件名用 {DATE}.json：

# 数据落盘目录约定
quant/market_overview/{DATE}.json   # data_market_overview(type=summary|trade)
quant/board_hot/{DATE}.json         # data_sector / data_hot(kind=board)
quant/quotes/{DATE}.json            # data_quote(持仓 codes)
quant/limitup/{DATE}.json           # tool_ranking(metric=limitup_days)
quant/lhb/{DATE}.json               # data_lhb
quant/news.json                     # 要闻，按 DATE 作 key 写入

2. 生成：

cd G:\ai\股票\quant
python build_dashboards.py --date {DATE}

产出 7 个页面：daily_overview / portfolio / hotmoney / lhb / lhb_{DATE}（归档）/ status_{DATE} / index（均在 web/）。

② 板块强度（可选，前瞻累积）

接口 data_sector 的 date 参数被忽略、只返「最新一个交易日」快照，故不回溯历史、不编造，走「前瞻累积」管道：

cd G:\ai\股票\quant
python collect_sector.py            # industry+concept 原始 JSON -> sector_strength_data_{DATE}.json
python run_daily_sector.py --date {DATE} --industry <file> --concept <file>
# 生成 web/sector-strength-{YYYYMMDD}.html(增强每日页) + sector-strength-trend.html + sector-strength-index.html

⚠️ 固化后务必 cat sector_trend.json 校验两天值不同；若雷同说明当日页用了旧数据，需重拉当日 industry+concept 重建。

③ 群体心理风险雷达（可选，单篇 + 索引）

采用 market-trend/_build_*.py 模板复制法：

# 以最近一期为模板，复制为新日期文件后定向改写静态值
cp market-trend/crowd-psychology-risk-radar-{PREV}.html \
   market-trend/crowd-psychology-risk-radar-{DATE}.html
# 用 _build_{DATE}.py 整块替换 I18N、BIAS 数组，并对 30+ 处静态值做断言替换
python market-trend/_build_{DATE}.py
# 同步更新 web/psychology/index.html（REPORTS 追加、stats、趋势图加第 N 点、notes）

硬性约束：所有数字来自真实查询、单文件离线 0 外链、右上角中英切换 + ?lang=、applyLang 用 innerHTML。

④ 自下而上选股（可选，每日一期）

依选股方法论（财务硬门槛 → 剔除周期顶点/低基数暴增/现金含量<0.5 → 逐只核 data_consensus 看 2027E/2028E 能否延续），产出常驻页：

web/bottom-up-stock-picks-{YYYYMMDD}.html   # 手动/半自动产出，不参与自动化门禁

⚠️ 与「个股信号池」（下一步）区分：本步是基本面自下而上的深度调研，频次可低；信号池是资金/信号驱动的每日双轨打分，必须每日跑。

⑤ 个股信号池（机构轨 + 游资轨，每日，必做）

第一步 · 候选聚合（纯本地数据，不依赖任何外网接口，最容易被漏跑）：

第二步 · 补拉打分数据（agent 经 MCP，按 _codes_{DATE}.txt 分批）：

第三步 · 双轨打分出页：

# 产出 web/picks/pick_{DATE}.html + web/picks/index.html；回填 history.json 次日/3日/5日表现

⚠️ 缺失数据自动降级为 0 分项，但 quotes_{DATE}.json 缺失会导致 0 行输出（无 price 直接跳过）。data_rating / data_consensus 为单码接口，逐只拉成本高，可略（对应维度记 0）；data_risk 降级时风险闸门与质押扣分不生效，需在页面标注。

⑥ 做T池（机构底仓网格，每日，必做）

⑦ 底部反转选股（每日重扫，必做）

目标：每个交易日收盘后，用「六步 Playbook」重新扫描全市场，刷新观察池，让 web/reversal/ 常驻版块始终保持最新。方法论常驻页 web/reversal/method.html 不变，只刷新观察池明细与入口摘要。

1. 经 westock 六步法实拉并落盘（由 agent 通过 MCP 执行，Python 脚本不可直接调 westock）：

quant/watchlist_scan_{DATE}.json
# 字段：data_date / presets{turnaround,main_inflow,low_pb} / candidates[{code,name,price,
#   float_mv,dist_52hi,ytd,pe,main20,rank,tier,score,logic,action}]

⚠️ 落盘 JSON 必须是纯 JSON：第一行起即为 {，任何 # 注释或 """docstring""" 都会让 gen_watchlist.py 的 json.load 直接失败；说明文字请放进 "_doc" 字段。

2. 生成：

3. 注入导航 + 主题 + 校验（与其他版块统一门禁）：

python _link_check.py           # 0 断链门禁
python _coverage_check.py --until {DATE}   # 校验 reversal 族 0 缺口、0 未登记、0 孤儿页

⚠️ gen_watchlist.py 的 scan_cases() 会扫描 web/reversal/ 下 songfa*.html / dajin_*.html 自动补入链消除孤儿页，案例页迁移到 web/reversal/ 后勿再放 web/research/，否则覆盖度自检会报孤儿。

⑧ MACD 水上金叉观察池（每日，自动化）

三层漏斗每日重扫，输出「趋势转多 × 资金进场」共振的强势候选（非个股推荐）：

cd G:\ai\股票\quant
# 1) Agent 经 westock-mcp 实拉并落盘（或复用既有 macd_raw_*.json）
python macd_build.py --raw      # 读 macd_raw_pool/tech/flow_{DATE}.json → 水上金叉 + 20日净流入为正
# 1b) 增强诊断列（记录项，不参与筛选）：另拉 data_quote + data_chip（对最终 35~51 只，约 2 次调用）
#     落 quant/macd_extra_{DATE}.json（字段 pos52/量比/换手/5D主力/归一化强度/60日涨幅/获利盘/集中度）
python _build_macd_extra_{DATE}.py   # 或由 Agent 直接按同一结构写盘（模板见 _build_macd_extra_0911.py）
# 2) 渲染 web/macd/index.html + watchlist_{DATE}.html + method.html
python gen_macd.py {DATE}

⚠️ 严格三层漏斗：tool_filter(main_inflow, min_inflow=0.3亿, market=hs) → data_technical(水上金叉 DIF>0&DEA>0&MACD红柱>0) → data_fund_flow(MainNetFlow20D>0)。剔除「当日热、20 日撤」的伪强势。

📊 各层数量随行情浮动，不写死：全市场初筛规模约 1500~2100 只（`tool_filter` 当日主力流入 > 0.3 亿的结果数），水上金叉层约 30~60 只，资金确认层再筛掉「20 日净流出」的伪强势。页面 KPI 与漏斗文案均由 gen_macd.py 用当日 pool_total / above_water 动态渲染，严禁在模板里硬编码某一天的数字（曾误写死「1488 只」与实际池 2092 只矛盾）。

📌 增强诊断列（52周分位 / 量比 / 换手 / 5日主力 / 归一化强度 / 60日涨幅 / 获利盘 / 集中度90）仅记录与标红警示，不参与筛选。原因：单期样本直接硬化阈值等于过拟合；先记录、累积 20~30 个交易日后回测分组胜率，再决定哪几条升级为硬条件。增强列缺失时页面自动降级显示「—」。另：候选表涨跌幅统一取 data_quote 收盘口径（初筛接口为盘中口径，个别股符号相反）。

三、已知坑（务必先看，避免重蹈覆辙）

⚠️ 收盘后指数 provisional 滞后：data_market_overview 收盘后 1~2 小时拉到的指数聚合是未定稿快照，晚间才定稿并可能显著上修（曾 18:20 拉到 3912.52，20:03 复拉定稿 3956.57）。硬性规则：指数必须晚间(20:00+)复拉确认，或对照已知锚点校验，绝不可收盘后即时拉一次就当最终指数发布。

⚠️ 聚合类接口滞后一个交易日：data_market_overview(summary/updown) 与 data_sector(mode=valuation) 返回的 date 是上一交易日；而 data_quote / data_technical 返回当日。报告里必须分别标注两类数据日期，不能统一写"当日"。
⚠️ 估值(PE 分位)接口滞后：最新快照常比主数据晚 1~2 天，生成器中用 --val-date 单独指定并在页面标注。
⚠️ data_sector 的 date 参数被忽略：只返最新一个交易日快照，无法按 date 回溯；整月历史回溯不可行，必须前瞻累积。
⚠️ 接口降级会直接打断日更（须每日核对新鲜度）：tool_ranking(limitup_days / margin_chg_d)、tool_event（解禁/减持/质押）、data_market_overview 一旦返回 error_type=2，会连锁导致：
  • ③ 群体心理雷达：连板梯队 / 两融环比 / 指数聚合缺失 → 无法整期重建（模板 130+ 键写死），只能停更；
  • ⑤ 个股信号池：quotes 拉不到 → 0 行输出；data_risk 缺失 → 风险闸门失效；
  • ⑥ 做T池：data_kline 大批量拉取受限 → 池子停更；
  • ⑧ MACD / ⑦ 反转：tool_filter 正常时不受影响，降级时同步停更。
纪律：每日收尾跑 python quant/_coverage_check.py --until {DATE}，凡「最新日期 ≠ {DATE}」的子系统即为漏跑/降级项 —— 能补的当天补；确因接口降级补不了的，必须在总门户诚实标注「接口降级·停更于 YYYY-MM-DD」，绝不可以用旧数据冒充当日、也不可静默跳过。
⚠️ I18N 键覆盖校验：用 re.finditer(r'([A-Za-z0-9_]+)\s*:') 抓取每行全部键；若用 re.match 只抓首键会误报大量"missing"。
⚠️ 模板复制法的共享尾串：同一叙事串（如「官方「狂热」标签虚高）。08-22~08-23 周末休市。」可能同时出现在 HTML 默认文本与 I18N 对象两处、字符微差；单次全局 str.replace 只命中其一、会静默吞掉另一处整句。须对两处分别用唯一上下文替换。
✅ 离线规则：单文件 HTML 必须 grep -c 'https\?://' = 0 且 <script src= = 0（选股报告用 echarts CDN 属例外，已确认）；涨=红、跌=绿（CSS .up/.down）。

四、校验清单（每期必过）

  • 外链：grep -c 'https\?://' 文件 应为 0（选股报告除外）
  • 脚本外引：无 <script src=（除非有意 CDN）
  • JS 语法：抽出 <script> 块，node --check 通过
  • I18N 覆盖：所有 data-i18n 键在 zh 与 en 块中均存在（缺失列表为空）
  • 趋势图：点数 = 期数；末点日期 = 最新
  • 无残留旧值：must_present / must_gone 断言通过（旧日期、旧数值不得残留）
  • 回链：各子系统页均有「← 返回总门户」指向 ../index.html
  • 覆盖度（新增·必做）：python quant/_coverage_check.py --until YYYYMMDD 输出 ALL_COVERED；非 0 退出码必须当天处理或记录为已知断档

五、全站覆盖度自检（每日收尾必跑）

目的：确保「每个该更新的页面族都更新到了目标交易日」，并揪出两类隐性残缺——日期断档与孤儿页（存在但没有任何页面链过去，用户点不到）。

  • 唯一权威来源：quant/_page_registry.py。新增页面必须在此登记，否则自检报 UNREGISTERED。
  • 自检脚本：python quant/_coverage_check.py --until YYYYMMDD [--since YYYYMMDD] [--json]

检查项

  • A 未登记页面：扫描到的 HTML 不在登记表内 → 补登记 or 删除
  • B/C 日期缺口与新鲜度：按日归档的族（status / lhb / sector / block / psychology / picks / tplus / reversal / macd）逐日比对交易日集合（自动剔除周末），缺期或最新日期≠目标日即报 GAP
  • D 孤儿页：无任何静态入链的页面；已排除 archive / db / docs 白名单
  • E 导航入口：_nav.SECTIONS 15 项必须全部存在（含「底部反转」）

孤儿页归位

python quant/_fix_orphans.py：按目录把孤儿页以「历史归档 / 相关页面」链接块（.section + .arch）插回所属索引页，带哨兵注释、可重复运行。跑完须重跑 _apply_theme.py 注入样式。

退出码

  • 0 全部通过（ALL_COVERED）
  • 1 存在覆盖缺口（B/C/D）→ 当天补或记录为已知断档
  • 2 结构性问题（A/E）→ 必须立即修
⚠️ 两类缺口要区分对待：
  • 页面未生成（数据在本地、只是没跑生成器）→ 直接补跑生成器；
  • 原始数据就没落盘（如 08-18 / 08-28 的 lhb / limitup / market_overview 全缺）→ 属历史漏采，补数据成本高，应登记为已知断档并在页面注明，绝不编造；板块强度（sector_daily）为前瞻累积，漏一天即永久断档，无法回补。

六、推送

通道：GitHub Contents API（urllib 逐文件 PUT），PAT 存于仓库外的 ~/.workbuddy/gh_pat.txt；目标仓库 dujoer/stocks@main。

  • python quant/_push_lhb.py：全量推送（os.walk(web) 兜底，单跑即推全部 web HTML）；推送时自动剥离 data-page-node-id 污染。
  • 禁止并发推送：分批并发会 409 抢写。收尾必跑 python quant/_sync_all.py，逐文件比对本地 git blob sha 与远程 sha，不一致才串行重推，一次收敛。
