二、每日盘后标准流程

① 龙虎榜主看板（必做，自动化）

1. 拉取并落盘（收盘后 ≥15:30，交易日）：用 westock-mcp 拉取并写文件到 quant/ 对应子目录，文件名用 {DATE}.json：

# 数据落盘目录约定
quant/market_overview/{DATE}.json   # data_market_overview(type=summary|trade)
quant/board_hot/{DATE}.json         # data_sector / data_hot(kind=board)
quant/quotes/{DATE}.json            # data_quote(持仓 codes)
quant/limitup/{DATE}.json           # tool_ranking(metric=limitup_days)
quant/lhb/{DATE}.json               # data_lhb
quant/news.json                     # 要闻，按 DATE 作 key 写入

2. 生成：

python quant/build_dashboards.py --date {DATE}

产出 7 个页面：daily_overview / portfolio / hotmoney / lhb / lhb_{DATE}（归档）/ status_{DATE} / index（均在 web/）。

② 板块强度（可选，前瞻累积）

接口 data_sector 的 date 参数被忽略、只返「最新一个交易日」快照，故不回溯历史、不编造，走「前瞻累积」管道：

python quant/collect_sector.py            # industry+concept 原始 JSON -> sector_strength_data_{DATE}.json
python quant/run_daily_sector.py --date {DATE} --industry <file> --concept <file>
# 生成 web/sector-strength-{YYYYMMDD}.html(增强每日页) + sector-strength-trend.html + sector-strength-index.html

⚠️ 固化后务必 cat sector_trend.json 校验两天值不同；若雷同说明当日页用了旧数据，需重拉当日 industry+concept 重建。

③ 群体心理风险雷达（每日，必做 —— 已全自动化）

已由「手抄文案」改为数据驱动生成器。旧方式 market-trend/_build_*.py（复制上一期页面 → 手抄 400+ 条中英文案 → 对 30~60 处精确字符串做 old→new 替换）已废弃，原因：替换锚点是「上一期的值」，上一期页面一旦被主题注入 / i18n 回写改动，锚点就静默失配（脚本只打印未命中），于是残留旧数据或直接放弃当日更新 —— 这正是该子系统历史上反复停更的根因。

# 前置（① 步已落盘）：quant/market_overview/{DATE}.json
# 前置（② 步产出）：quant/sector_strength_data_{YYYYMMDD}.json
# 连板梯队（当日，MCP 拉取后落盘）：
tool_ranking(metric=limitup_days, date={DATE}) → quant/psy/limitup_{DATE}.json

# 一键生成（无需手写任何文案）：
python quant/build_psychology.py --date {DATE}
# 节假日/调休导致下一交易日不是自然次日时：
python quant/build_psychology.py --date {DATE} --next {NEXT_DATE}

# 产出：
#   web/psychology/crowd-psychology-risk-radar-{YYYYMMDD}.html
#   自动追加 web/psychology/index.html 的 REPORTS 条目
#   自动写入 quant/psy/history.json（供下期环比与雷达融资维平移）

数据流：广度 / 指数 / 技术 / 估值 / 风格 ← data_market_overview；板块领涨领跌与主力行为 ← 板块强度 sector_strength_data_{YYYYMMDD}.json；连板梯队 ← tool_ranking(limitup_days)。阶段定性（恐慌扩散 / 退潮加速 / 广度修复 / 情绪回暖 / 指数分化 / 缩量震荡）、风险等级、雷达六维均由脚本内的显式规则计算；中英文叙述由模板按真实数据拼装。任一数据缺失即如实标注「接口降级，未编造」。

校验：脚本收尾会打印「残留旧数据」，必须为「无」。若不为无，说明固定骨架 quant/psy/_skeleton.html 的某处正则锚点失配，修对应位置的正则即可（骨架只读，不可改数值）。

⚠️ hub 顶部静态块必须单独刷新（曾停在 09-11）：build_psychology.py 只把新一期「追加」进 web/psychology/index.html 的 REPORTS 数组；而 hub 顶部的涨股比走势 SVG（折线点位 / 数值标签 / 日期轴）、走势注记、情绪周期轨迹注记、统计条、跨度标签都是静态文本，不会随 REPORTS 自动走 —— 历史上靠 market-trend/_update_index_{MMDD}.py 手改，一旦漏跑就永久停在旧日期（实测 2026-09-20 时 REPORTS 已有 25 期，走势图与注记仍停在 09-11）。现已改为脚本收尾自动调用 quant/psy_hub_refresh.py（幂等，以 hub 自身 REPORTS 为唯一真相源重建上述静态块）。体检 / 补刷：
python quant/psy_hub_refresh.py --check　# 落后会返回退出码 1
python quant/psy_hub_refresh.py　　　　　# 补刷

④ 自下而上选股（可选，每日一期）

依选股方法论（财务硬门槛 → 剔除周期顶点/低基数暴增/现金含量<0.5 → 逐只核 data_consensus 看 2027E/2028E 能否延续），产出常驻页：

web/bottom-up-stock-picks-{YYYYMMDD}.html   # 手动/半自动产出，不参与自动化门禁

⚠️ 与「个股信号池」（下一步）区分：本步是基本面自下而上的深度调研，频次可低；信号池是资金/信号驱动的每日双轨打分，必须每日跑。

⑤ 个股信号池（机构轨 + 游资轨，每日，必做）

第一步 · 候选聚合（纯本地数据，不依赖任何外网接口，最容易被漏跑）：

python quant/gen_picks.py --date {DATE} --window 20 --top 40
# 读：quant/q2_full/_merged_shareholder.json（中报十大股东）
#     quant/exec_chg/{DATE}.json（高管增减持，近 20 交易日）
#     quant/block_chg/{DATE}.json（大宗交易，近 20 交易日）
#     quant/lhb/{DATE}.json（龙虎榜 jg 机构席位 / yyb 营业部）
# 产出：quant/picks/candidates_{DATE}.json + quant/picks/_codes_{DATE}.txt（每批 25 只）

第二步 · 补拉打分数据（agent 经 MCP，按 _codes_{DATE}.txt 分批）：

# 每批 ≤25 只（data_technical / data_chip 限频）
data_quote        → quant/picks/quotes_{DATE}.json
data_technical    → quant/picks/technical_{DATE}.json   (group=ma,macd,rsi,kdj,boll)
data_chip         → quant/picks/chip_{DATE}.json
data_fund_flow    → quant/picks/fundflow_{DATE}.json
data_fund_margin  → quant/picks/margin_{DATE}.json
data_hot(kind=stock) → quant/picks/hot_{DATE}.json
# 字段映射见 quant/_relay_picks_0914.py（可复用为 relay 模板）

第三步 · 建日K价格档案（沙箱外，必做 —— 漏跑则次日无法回填昨日选股）：

python quant/fetch_pick_klines.py --end {DATE}
# 产出 quant/picks/price_archive.json（逐码 × 逐日 OHLC，data_kline 拉取）

⚠️ 回填的价格源是这份档案，不是 quotes_{DATE}.json。quotes 只含当日候选，用它回填的话只有「连续两日都入选」的票才有 T+1/T+3/T+5，多数票永远无回测 —— 这正是历史上回测长期缺数的根因。

第四步 · 双轨打分出页：

python quant/build_picks.py --date {DATE}
# 产出 web/picks/pick_{DATE}.html + web/picks/index.html；
# backfill 读 price_archive，按真实交易日历把每只票的次日/3日/5日表现回填（昨日选股今日结算），
# 并用真实同日收盘 + MA5 校正入场/止损/目标基准，消除陈旧 MA5 造成的收益虚高

⚠️ 缺失数据自动降级为 0 分项，但 quotes_{DATE}.json 缺失会导致 0 行输出（无 price 直接跳过）。data_rating / data_consensus 为单码接口，逐只拉成本高，可略（对应维度记 0）；data_risk 降级时风险闸门与质押扣分不生效，需在页面标注。

⚠️ 关于「改权重」的纪律（2026-09-21 起，重要）：绝不要照回测页的分档胜率去调 11 维权重。 现有权重是 2026-09-18 按「近 5 期实测归因」调的 —— 5 期约 100 个样本、且全部落在同一波行情里，属于典型的样本内过拟合， 回测页自身已给出反证（机构轨 B 档 T+1 胜率仅 36%，最低的 D 档 T+5 反而 +5.74%、胜率 83%，分档与收益反向）。 需要评估某个因子/某个池的选股能力时，一律走样本外实验室，不要凭近期样本改参数。

第五步 · （按需）跑样本外实验室与稳健分：

python quant/_pick_lab.py                    # 47 特征 × 13,630 样本点，五道独立检验 → web/picks/lab.html
python quant/pick_score.py --date {DATE}      # 稳健分（build_picks 已自动调用，此处用于单独核对）

实验室已固化的三条结论： ① 「自动筛因子」这个动作本身就是主要噪声源 —— 用前 60% 数据筛出因子再测后 40%，相对胜率只剩 +0.5pp； 而同一批数据下「用全量筛因子」能报出 +8.2pp，7.7pp 的差额就是过拟合的量。 ② 因此稳健分采用先验固定因子集（价量 5 项 + 基本面 7 项，方向由经济逻辑给定、等权、不按回测调权重）， 在当日候选内做横截面分位；留出段 相对胜率 +4.3pp / 绝对胜率 +1.0pp，6 段滚动全部为正。 ③ 环境门控比选股更值钱：同样一批异动票，弱势环境（全市场广度低）「随便买」绝对胜率仅 40.9%， 强势环境 51.1%，差 10.1pp —— 比选股能带来的 1~3pp 大得多。 故弱势期该做的是降暴露而非继续精挑细选；pick_score.env_state() 已按广度输出仓位系数（≥55%→1.0 / ≥35%→0.7 / 否则 0.4）， 页面顶部「环境门控」横幅会自动显示当日系数。

⑥ 做T池（三源并集网格，每日，必做）

# 源B 龙虎榜：quant/lhb_enriched_*.json 近 10 交易日，累计净买 >0 或 ≥2 次上榜（约 220 只）
# 源C 强势：第一步产物再过做T结构门槛，取 RS20 前 400 只
# 产出 quant/tplus/codes_{DATE}.txt + universe_{DATE}.json（约 1600 只，逐只带 sources 标签）

第三步 · 补拉行情 + 日K（推荐离线腾讯通道，无 MCP 限额）：

python quant/fetch_tplus_offline.py {DATE}
# 腾讯 qt 快照 + fqkline 日K（250 根）→ quant/tplus/quotes_{DATE}.json / kline_{DATE}.json
# 复用缓存 quant/_txk_cache.json（增量约 700 只，1~2 分钟）；无网时再用 data_quote / data_kline 分批

第四步 · 打分出页：

python quant/build_tplus.py --date {DATE}
# 产出 web/tplus/index.html + web/tplus/tplus-{DATE}.html
# 打分 7 维：波动24 + 流动16 + 区间20 + 资金底仓12 + 稳定8 + 龙虎榜共振8 + 强势结构12 − 风险
# 页面板块：做T榜单(全量) / 强势股分析 / 龙虎榜视角 / 网格手册 / 波段手册 / 方法论 / 归档

⚠️ 三源并集后候选约 1600 只（原 848 只），务必走离线腾讯通道（fetch_tplus_offline.py），MCP data_kline 拉 1600×250 根会严重限频。日K缓存 quant/_txk_cache.json 是关键，缺失时会显著变慢。漏跑会导致做T池停更在上一交易日。

检查项

  • A 未登记页面：扫描到的 HTML 不在登记表内 → 补登记 or 删除
  • B/C 日期缺口与新鲜度：按日归档的族（status / lhb / sector / block / psychology / picks / tplus / reversal / macd）逐日比对交易日集合（自动剔除周末），缺期或最新日期≠目标日即报 GAP
  • D 孤儿页：无任何静态入链的页面；已排除 archive / db / docs 白名单
  • E 导航入口：_nav.SECTIONS 15 项必须全部存在（含「底部反转」）

孤儿页归位

python quant/_fix_orphans.py：按目录把孤儿页以「历史归档 / 相关页面」链接块（.section + .arch）插回所属索引页，带哨兵注释、可重复运行。跑完须重跑 _apply_theme.py 注入样式。

退出码

  • 0 全部通过（ALL_COVERED）
  • 1 存在覆盖缺口（B/C/D）→ 当天补或记录为已知断档
  • 2 结构性问题（A/E）→ 必须立即修
⚠️ 两类缺口要区分对待：
  • 页面未生成（数据在本地、只是没跑生成器）→ 直接补跑生成器；
  • 原始数据就没落盘（如 08-18 / 08-28 的 lhb / limitup / market_overview 全缺）→ 属历史漏采，补数据成本高，应登记为已知断档并在页面注明，绝不编造；板块强度（sector_daily）为前瞻累积，漏一天即永久断档，无法回补。

六、推送

通道：GitHub Contents API（urllib 逐文件 PUT），PAT 存于仓库外的 ~/.workbuddy/gh_pat.txt；目标仓库 dujoer/stocks@main。

  • python quant/_push_lhb.py：全量推送（os.walk(web) 兜底，单跑即推全部 web HTML）；推送时自动剥离 data-page-node-id 污染。
  • 禁止并发推送：分批并发会 409 抢写。收尾必跑 python quant/_sync_all.py，逐文件比对本地 git blob sha 与远程 sha，不一致才串行重推，一次收敛。
  • 沙箱：Bash 沙箱会拦截 GitHub 外网，推送须关闭沙箱执行，否则无输出。
  • 推送后抽检：python quant/_curl_gate.py，关键页（index / exec / picks / tplus / db 的 index.html、lhb_{D}、block_{D}、sector-strength-YYYYMMDD）须全 200。Pages 构建有约 1 分钟延迟。
