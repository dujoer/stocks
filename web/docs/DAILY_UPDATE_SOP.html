二、每日盘后标准流程

① 龙虎榜主看板（必做，自动化）

1. 拉取并落盘（收盘后 ≥15:30，交易日）：用 westock-mcp 拉取并写文件到 quant/ 对应子目录，文件名用 {DATE}.json：

# 数据落盘目录约定
quant/market_overview/{DATE}.json   # data_market_overview(type=summary|trade)
quant/board_hot/{DATE}.json         # data_sector / data_hot(kind=board)
quant/quotes/{DATE}.json            # data_quote(持仓 codes)
quant/limitup/{DATE}.json           # tool_ranking(metric=limitup_days)
quant/lhb/{DATE}.json               # data_lhb
quant/news.json                     # 要闻，按 DATE 作 key 写入

2. 生成：

cd G:\ai\股票\quant
python build_dashboards.py --date {DATE}

产出 7 个页面：daily_overview / portfolio / hotmoney / lhb / lhb_{DATE}（归档）/ status_{DATE} / index（均在 web/）。

② 板块强度（可选，前瞻累积）

接口 data_sector 的 date 参数被忽略、只返「最新一个交易日」快照，故不回溯历史、不编造，走「前瞻累积」管道：

cd G:\ai\股票\quant
python collect_sector.py            # industry+concept 原始 JSON -> sector_strength_data_{DATE}.json
python run_daily_sector.py --date {DATE} --industry <file> --concept <file>
# 生成 web/sector-strength-{YYYYMMDD}.html(增强每日页) + sector-strength-trend.html + sector-strength-index.html

⚠️ 固化后务必 cat sector_trend.json 校验两天值不同；若雷同说明当日页用了旧数据，需重拉当日 industry+concept 重建。

③ 群体心理风险雷达（可选，单篇 + 索引）

采用 market-trend/_build_*.py 模板复制法：

# 以最近一期为模板，复制为新日期文件后定向改写静态值
cp market-trend/crowd-psychology-risk-radar-{PREV}.html \
   market-trend/crowd-psychology-risk-radar-{DATE}.html
# 用 _build_{DATE}.py 整块替换 I18N、BIAS 数组，并对 30+ 处静态值做断言替换
python market-trend/_build_{DATE}.py
# 同步更新 web/psychology/index.html（REPORTS 追加、stats、趋势图加第 N 点、notes）

硬性约束：所有数字来自真实查询、单文件离线 0 外链、右上角中英切换 + ?lang=、applyLang 用 innerHTML。

④ 自下而上选股（可选，每日一期）

依选股方法论（财务硬门槛 → 剔除周期顶点/低基数暴增/现金含量<0.5 → 逐只核 data_consensus 看 2027E/2028E 能否延续）：

python build_picks.py --date {DATE}   # 或手动产出 web/bottom-up-stock-picks-{YYYYMMDD}.html

⑥ 刷新总门户 + 校验

python build_portal.py    # 重建总门户，自动带出各子系统最新日期与新鲜度

随后做 第四节校验清单。

三、已知坑（务必先看，避免重蹈覆辙）

⚠️ 收盘后指数 provisional 滞后：data_market_overview 收盘后 1~2 小时拉到的指数聚合是未定稿快照，晚间才定稿并可能显著上修（曾 18:20 拉到 3912.52，20:03 复拉定稿 3956.57）。硬性规则：指数必须晚间(20:00+)复拉确认，或对照已知锚点校验，绝不可收盘后即时拉一次就当最终指数发布。

⚠️ 聚合类接口滞后一个交易日：data_market_overview(summary/updown) 与 data_sector(mode=valuation) 返回的 date 是上一交易日；而 data_quote / data_technical 返回当日。报告里必须分别标注两类数据日期，不能统一写"当日"。
⚠️ 估值(PE 分位)接口滞后：最新快照常比主数据晚 1~2 天，生成器中用 --val-date 单独指定并在页面标注。
⚠️ data_sector 的 date 参数被忽略：只返最新一个交易日快照，无法按 date 回溯；整月历史回溯不可行，必须前瞻累积。
⚠️ I18N 键覆盖校验：用 re.finditer(r'([A-Za-z0-9_]+)\s*:') 抓取每行全部键；若用 re.match 只抓首键会误报大量"missing"。
⚠️ 模板复制法的共享尾串：同一叙事串（如「官方「狂热」标签虚高）。08-22~08-23 周末休市。」可能同时出现在 HTML 默认文本与 I18N 对象两处、字符微差；单次全局 str.replace 只命中其一、会静默吞掉另一处整句。须对两处分别用唯一上下文替换。
✅ 离线规则：单文件 HTML 必须 grep -c 'https\?://' = 0 且 <script src= = 0（选股报告用 echarts CDN 属例外，已确认）；涨=红、跌=绿（CSS .up/.down）。

四、校验清单（每期必过）

  • 外链：grep -c 'https\?://' 文件 应为 0（选股报告除外）
  • 脚本外引：无 <script src=（除非有意 CDN）
  • JS 语法：抽出 <script> 块，node --check 通过
  • I18N 覆盖：所有 data-i18n 键在 zh 与 en 块中均存在（缺失列表为空）
  • 趋势图：点数 = 期数；末点日期 = 最新
  • 无残留旧值：must_present / must_gone 断言通过（旧日期、旧数值不得残留）
  • 回链：各子系统页均有「← 返回总门户」指向 ../index.html

五、推送

⚠️ 当前 GitHub 推送被两处鉴权阻塞（需你侧处理）：
  • 旧 PAT 已撤销 → REST 脚本推送 401；
  • GitHub MCP 连接器 push_files 返回 403（App 未获授权访问 dujoer/stocks）。

解法（任选）：① 在 dujoer 账号重新授权 GitHub MCP 连接器 App 后重试；② 提供具备 repo 权限的新 PAT，用 stdlib REST 脚本推送；③ 本地 git / 网页手动上传 web/ 与 market-trend/。
