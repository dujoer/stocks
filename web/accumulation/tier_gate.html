增仓精选 · 分档规则显著性检验

主判定窗口 2026-06-09 ~ 2026-09-01 （60 个入场日，每笔前瞻均走满 20 根）｜ 面板 2827 笔 ｜ bootstrap 2000 次按日整块重抽 × 三个随机种子取保守值
为什么会有这一页。 生产 build_accum.scan() 是全候选域按规则分档（当日 S / A / B 全部出票）， 而 lab.html 与 accum_result.json 评估的是每日 composite 得分 top25 —— 两者不是同一批票，页面给每档标的胜率未必是实际出票那批。 另外页面把 A 档写成「≥3 共振且（M 或 I）」、却标注 59.4%（那是「M 且 I」的数字）， 规则与数字对不上。本页按生产真实分档定义在全候选域上重建面板， 用主升/做T 门控同一套方法（逐日平衡 edge + block bootstrap + R3 + 留一法 + walk-forward）重新判定。
已发现问题：A 档（现行生产「≥3共振且 M 或 I」）的逐日平衡超额为负（-1.15 pp，R3 最低仅 2%，绝对收益 -0.54% 也低于不筛选的候选域 -0.19%）。也就是说按现行规则出票的那一档，还不如不筛选；且窗口拉长到 60 个入场日后负值更大 —— 这不是噪声，是稳定负贡献。
候选改法「≥3共振且 M 且 I」在同一批样本上超额为 +1.33 pp（R3 97%），但它是在这批样本里挑出来的赢家，本页不采纳为出票依据，只作对照。

五、局限与口径声明

  • 分档定义逐字复刻 build_accum.scan()：S = 5 日融资净买入占比 ≥4% 且机构/私募季度增持；A = ≥3 信号共振且（M 或 I）；B = 恰 2 个信号。
  • 退出生效参数沿用 _accum_lab：止损 −12% ／ +6% 激活 ／ 回撤 3% 跟踪 ／ 满 20 日强平； 入场日只取前瞻已走满 20 根的那些。
  • 对照口径是同日全候选域（当日触发过至少一个日频事件、且合成分为正的全体）， 故「全候选域（无筛选对照）」那一行 edge 恒为 0，只用来看它的绝对水平。
  • 机构/私募维度来自季度股东快照，把它套到历史入场日天然带有后见偏差； 这是该数据集的既有属性，本页不做修正，只在此声明。
  • 主判定窗口只有 60 个入场日、2827 笔， 且早期每天候选只有几十只、后期上百只（数据可得性随时间变宽，窗口本身不均匀）； 逐日平衡会把「几十只的日子」和「上百只的日子」等权，这是本页刻意的保守处理。 按项目红线，达不到 R3 门槛的一律判「不可判」，不作为出票依据。
  • 本页只做「现有规则有没有超额」的判定，不做规则改良：候选改法那一行只用于对照， 不代表改用它就能赚钱（在同一批样本上挑赢家本身即是过拟合）。
